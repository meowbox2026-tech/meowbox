# MeowBox｜前二十五關難度公式與驗證

版本：2026-09-23。本公式只驗證目前 1–25 關配置解謎；26 關以後沒有資料，不使用這套分數假裝預測未設計內容。

## 先固定問題

每關在固定 8×8 盤面上，先有 `I` 隻固定貓，再依順序放入 `T` 隻托盤貓。合法放置只檢查座標、空格與托盤順序；玩家按開始後，遊戲用同一個 deterministic engine 依放置順序逐群完成消除、支撐落下與連鎖優先。

```text
A = 64                         棋盤面積
N = I + T                      最終總貓數
E = A - I                      開始配置時的空格數
W = 完整解答的消除波數
G = 解答中存活貓咪向下移動的總格數
K = 托盤使用的貓咪種類數
```

關卡不因為「貓比較多」就自動合理；必須同時回答：作者解答能否清空、玩家需要預判幾波、放錯後是否仍有可理解的替代路線，以及相鄰關卡是否平滑。

## 難度分數

先把每個指標壓到 0–1，再加權：

```text
D = 100 × (
      0.25 × S   搜尋空間
    + 0.10 × C   解答緊度
    + 0.20 × H   連鎖波數
    + 0.20 × Gᵣ  局部重力
    + 0.10 × R   方向切換
    + 0.10 × F   盤面密度
    + 0.05 × P   貓咪種類
)
```

### `S` 搜尋空間

```text
S = clamp(log10(E! / (E - T)!) / 30, 0, 1)
```

程式以逐項 `log10(E - i)` 相加，不直接計算巨大階乘。`30` 是目前 8×8、最多 21 隻托盤貓的校準上限；若棋盤尺寸改變，必須重新校準。

### `C` 解答緊度

用正式 `resolvePlanning` 把每隻解答貓單獨搬到其他空格，統計仍能清空的附近替代解：

```text
alternativeRate = 可清空的單格搬移數 / 單格搬移測試數
C = 1 - alternativeRate
forcedPlacementRate = 沒有任何替代位置的托盤貓數 / T
```

`forcedPlacementRate >= 85%` 且 `alternativeRate <= 1%` 時標示 `solution-too-brittle`。這是要求補足視覺線索或調整盤面，不是要用生命或廣告懲罰玩家。

### `H` 連鎖波數、`Gᵣ` 重力

```text
H  = clamp((W - 2) / 12, 0, 1)
Gᵣ = clamp(G / (2N), 0, 1)
```

兩波視為基本理解成本。重力只計算消除後仍存活的貓向下移動距離，不把被消除的貓當成重力負擔。

### `R` 方向切換、`F` 密度、`P` 種類

```text
coverage       = clamp((不同基本方向數 - 1) / 2, 0, 1)
switchRate     = 方向改變次數 / max(1, W - 1)
R              = clamp(0.65 × coverage + 0.35 × switchRate, 0, 1)
F              = clamp(N / 64, 0, 1)
P              = clamp((K - 3) / 2, 0, 1)
```

方向只計橫、直、兩種斜線；`mixed` 是同一波含多個幾何關係的輸出，不是新的配對規則。

## 章節目標與跳幅

分數是設計工具，不是玩家看到的評分。允許同章有教學關、舒緩關與收尾關，但相鄰關卡分數變化不得超過 10；超過就必須重新檢查，不能用「玩家多試幾次」合理化。

| 關卡 | 目標分數 | 章節責任 |
| --- | ---: | --- |
| 1–3 | 28–38 | 基礎方向與第一次連鎖 |
| 4–10 | 35–55 | 第四種貓與簡單混合 |
| 11–15 | 44–62 | 支撐、順序與分支 |
| 16–20 | 50–72 | 低分支過渡、可預測重力 |
| 21–25 | 62–80 | 高密度收尾，但仍需可讀 |

16–20 的重點不是再加規則，而是在維持 `26/28/30/32/36` 初始貓數與 `13/14/15/16/18` 托盤量的同時，從橫向貨架、中央棋盤到支撐鏈逐步增加可預測重力。21–25 改成 `31/32/36/39/39` 初始貓與 `16/17/18/21/21` 托盤貓，讓 20→21 不再突然跳到最高密度。若實測仍造成高失敗率，先改盤面分支，再考慮調低數量。

## 條件卡的計算規則

每關托盤上方顯示作者路線的條件摘要，欄位由 `resolvePlanning` 的 frame 直接反算：

```text
horizontal / vertical / diagonal = 該方向的有效連線條數
groups                          = 逐波實際消除的群組數
totalClearingCells              = 所有群組清除格子的聯集總數；介面顯示為「清除格」
largestGroup                    = 單一群組的最大不重複格數
gravityWaves                    = 有存活貓實際向下移動的波數
```

`groups` 只供 resolver、分析器與測試使用，不直接顯示在條件卡。介面隱藏 0 值，方向與數量用 `━×4`、`┃×2`、`╱×1` 等短符號呈現。

這張卡是教玩家讀懂作者設計，不是新增一個「必須走唯一路線」的成功條件。交叉線共用的格子只算一次；所有合法替代路線仍由完整可解性搜尋判定。

## 有效關卡的硬性檢查

一關只有在以下條件全部成立時才可進入主線：

1. `arrangeCats(level, level.solution)` 成功，沒有重複、越界或空格衝突。
2. `resolvePlanning(solutionBoard).remaining === 0`。
3. 初始固定盤面沒有玩家尚未配置就成立的三連。
4. 每一個消除波、清除 ID 與重力結果都能由 frame 重播。
5. 關卡沒有生命、不扣生命；完整配置結算失敗只回到乾淨的配置狀態，不保留半盤。
6. 條件卡的群組格數使用 8 向連通聯集，不能把交叉線重複計算；落下形成的連鎖必須先清完，再處理原本群組；提示顯示安全建議，不把作者解答宣稱為唯一答案；150ms 背景搜尋只服務提示，不作放置合法性判定。
7. 第 25 關是最後一關，完成後不產生第 26 關。

## 分析工具的解讀

```bash
npm run analyze:planning
```

- `authored-solution-does-not-fit`／`authored-solution-does-not-clear`：關卡無效，不能上線。
- `outside-target-band`：章節定位不符，先看是哪一項指標過高。
- `jump-too-large`／`drop-too-large`：相鄰體感可能斷層，必須調整前後關卡。
- `solution-too-brittle`：玩家可能不知道為什麼錯，先補可讀性或替代路線。

玩家實測還要記錄首次成功率、平均失敗次數、提示使用率、失敗後重新配置成功率與退出率。沒有這些資料前，不能宣稱某個分數差距等於固定的體感差距。
