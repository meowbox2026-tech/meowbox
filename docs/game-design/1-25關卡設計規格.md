# MeowBox｜1–25 關卡設計與結算規格

版本：2026-09-23。這是目前 1–25 關的長期對照文件；引擎、測試、遊戲內規則文案與關卡資料若有歧異，以本文件描述的狀態轉移與測試為準。26–100 關只能在完成本文件所列的延伸驗證後加入。

## 1. 一局的固定流程

1. 棋盤固定為 8×8，固定盤面先存在；托盤貓依資料順序逐隻出現，不能跳過或交換。
2. 配置階段只能把下一隻托盤貓放進合法的空格：座標在棋盤內、格子未佔用、且使用目前托盤順序的貓。配置階段不消除、不落下、不移動固定貓。
3. 合法性只指上述操作條件，不由可解性搜尋決定。沒有立即三連、不是作者路線、或需要後續支撐落下，都不會讓放置變成錯誤。
4. 全部托盤貓放完後才能按「開始」。正式結算使用與關卡驗證相同的 `resolvePlanning`。
5. 結算清空全部貓咪即過關；仍有貓咪時只重置本次配置，回到空托盤重新安排。

## 2. 不扣生命與失敗邊界

1. 本玩法沒有生命值，也不扣生命；不能因為一個合法位置被搜尋器判定為不理想而中斷玩家。
2. 配置失敗只重置本次配置：清除本次放置、結算 frame、選取狀態與本次撤銷狀態；不保留半盤，不接續錯誤結算。
3. 點到已佔格、越界或不符合托盤順序的操作只被拒絕，不算失敗、不扣生命。重複放置、未知貓咪與溢出配置同樣拒絕。
4. 每次配置有 1 次撤銷；每關有 1 次提示。配置失敗不恢復已用提示，整關重新開始才重置關內資源。

## 3. 提示與 150ms 背景搜尋

提示搜尋在背景 worker 執行，等待上限為 150ms（`PLANNING_CHECK_TIMEOUT_MS`）。它只負責在玩家按下提示後尋找一個已驗證可接續的位置：

- 搜尋成功才顯示建議位置；多解時不能宣稱作者路線是唯一答案。
- 150ms 超時、worker 不可用或搜尋錯誤，只代表這次沒有提示結果；不代表無解、不拒絕放置、不扣生命。
- 放置事件不等待提示搜尋，也不呼叫可解性搜尋作為放置合法性判定。放置只使用座標、空格與托盤順序檢查。
- `canCompletePlanning` 與同步搜尋可供離線關卡驗證和測試使用，不得成為配置階段的錯誤門檻。

## 4. 消除群組、支撐與連鎖優先

正式結算每一波只消除一個群組，不能把同時存在的群組一次全部刪除：

1. 找出同款貓咪在橫、直或兩種斜線上連續 3 隻以上的有效格。
2. 同色且參與有效連線的格子，只要以 8 個方向相連，就合併為一個群組；交叉格只算一次。
3. 第一組依群組內最小的放置順序決定。若候選群組沒有托盤放置數字，才用上到下、左到右的固定位置作平手順序。
4. 清除該群後，只處理被清除格直接支撐、且上方沒有空洞的連續堆疊；中間隔著空格的貓咪不會被拉下來。
5. 重力後重新找群組。只要落下造成新群組，或讓原群組中的貓咪移動而形成可消除群，就把它視為目前連鎖，必須先把這段落下連鎖全部清完。
6. 連鎖佇列清空後，才回頭處理清除前原本已存在、尚未處理的其他群組；這些群組仍依放置順序選擇。每次清除與落下都產生可重播的 frame。

簡化狀態轉移如下：

```text
全部放置
  → 原始群組：依放置順序選第一組
  → 清除一組
  → 失去支撐的連續堆疊落下
  → 有落下連鎖？是 → 先清完所有連鎖 → 再看原始群組
                         否 → 依放置順序處理下一個原始群組
  → 沒有群組：清空則過關，仍有貓則重置本次配置
```

## 5. 1–25 關章節與難度意圖

所有關卡維持同一套 8×8、三連、8 向群組、局部支撐落下與連鎖優先規則。難度只透過版型、密度、方向、支撐深度、路線分支和托盤量漸進，不新增隱藏判定。

| 關卡 | 固定貓 | 托盤貓 | 章節意圖 |
| --- | ---: | ---: | --- |
| 1–5 | 6/8/10/12/14 | 3/4/5/6/7 | 認識固定盤面、托盤順序、三連與第一次連鎖 |
| 6–10 | 16/18/20/20/20 | 8/9/10/10/10 | 斜線、混合方向、局部重力與多個可讀落點 |
| 11–15 | 20/20/22/22/24 | 10/10/11/11/12 | 連鎖接力、鏡像辨識、密度提高但保留替代路線 |
| 16–20 | 26/28/30/32/36 | 13/14/15/16/18 | 逐步增加支撐鏈與讀盤壓力；左側輪廓每關必須可辨識，不重用同一個左半場 |
| 21–25 | 31/32/36/39/39 | 16/17/18/21/21 | 專家章節：右側分支、偏移鏡像、密集主體、中央合流、不同路線順序的收束 |

21–25 是目前主線的內容邊界，不是玩法規則的終點。第 25 關完成後只顯示主線完成，不自動推導第 26 關。相鄰難度須以 `npm run analyze:planning` 檢查，若跳幅過大先改版型與分支，再考慮增加數量。

## 6. 26–100 關延伸原則

- 26–30 先延續 1–25 的結算規則，只增加一個可見的主要壓力（例如更長支撐鏈或一次偏移合流），不能同時引入新消除型態、隨機補貓和新失敗條件。
- 31–50 可按章節加入一種新方向或版型變因；每章要有教學、練習、組合與舒緩關，不能連續五關只堆密度。
- 51–75 才考慮新的群組效果或可預知的落下模式；新增效果必須先定義停止條件、群組優先、可重播 frame 與提示語意。
- 76–100 用於組合已驗證機制，不以單純增加貓數製造難度；每關都要保留至少一條作者解與多解容許策略。
- 所有新章節必須先通過：初始盤面無免費消除、作者解可清空、替代路線政策明確、落下連鎖優先測試、提示 150ms 超時測試、配置失敗只重置測試，以及相鄰難度曲線檢查。
- 除非另立並通過新的產品規格，不得恢復生命、扣生命、配置階段可解性攔截或半盤續玩；這些都不是 1–25 的默認規則。

## 7. 對照測試與重播命令

規則優先序由 `src/game/core/planningEngine.test.ts` 的「clears a gravity cascade before returning to another original group」鎖定；配置邊界、無生命重置與提示背景搜尋則由 `src/game/phaser/planningState.test.ts`、`src/app/screens/PlanningGameScreen.test.tsx` 與 `src/game/core/planningSolvabilityAsync.test.ts` 覆蓋。

關卡資料需通過：

```text
npx vitest run src/game/core/planningEngine.test.ts src/game/data/planningLevels.test.ts
npm run analyze:planning
npm run lint
npm run build
```

`analyze:planning` 的重播必須確認 1–25 關作者解可清空、所有關卡通過匯入驗證、沒有初始免費群組，且難度沒有超過設定的相鄰跳幅上限。
