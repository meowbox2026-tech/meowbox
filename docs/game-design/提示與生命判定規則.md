# MeowBox｜提示、三條生命與可見目標規則

版本：2026-09-23。這是[第 15–100 關重新設計研究](./第15至100關重新設計研究.md)的配套規格，專門處理「什麼叫做錯誤」、「提示怎麼保證正確」以及「如何把玩法延伸到數百關」。

## 核心決定

提示不能只找「現在能消除」的欄位；它必須確認這一步之後仍然存在完成路線。三條生命也不能因為沒有立即消除就扣，只有已被完整規則證明會進入死路的操作才扣生命。

因此：

- 合法但沒有立即消除，可能是正確的整理步，不扣生命。
- 現在分數較低但之後仍可過關，是次佳解，不扣生命。
- 只有確定無法完成目標的操作才是 `dead`，扣一條生命並回復到操作前。
- 搜尋器無法判定時回傳 `uncertain`，不能把不確定當作錯誤。
- 提示若存在多條同樣安全的路線，應顯示「建議」或多個安全選項，不宣稱唯一答案。

## 完整可解性判定

令：

- `S`：棋盤、目前貓、隊列、目標進度、剩餘回合與目前模式的完整狀態。
- `A(S)`：從 `S` 出發的所有合法格子或欄位。
- `resolve(S, a)`：執行操作 `a`，完整結算同時消除、四／五連效果、重力與後續 wave 後的狀態。
- `CanFinish(S)`：從狀態 `S` 出發，在剩餘回合與目標條件內是否存在至少一條完成路線。

```text
CanFinish(S) = 已達成所有通關目標
             或 存在 a ∈ A(S)，使 CanFinish(resolve(S, a)) = true
```

實際搜尋要把以下資料放入狀態簽名：

- 棋盤上每隻貓的類型、特殊效果與位置。
- `current`、`next`、預覽隊列位置與固定 seed。
- 救援數量、四連／五連／連鎖／斜線計數。
- 剩餘回合、剩餘生命與障礙物狀態。

搜尋遇到相同狀態要去重；同時保存不同第一步的 witness。若使用隨機 bag，主線前段仍應使用固定隊列。進入隨機段後，提示可用多個 seed 測試成功比例；不能因單一幸運 seed 找不到而直接判玩家錯誤。

### 操作分類

| 操作結果 | 是否扣生命 | 說明 |
| --- | --- | --- |
| 滿欄、障礙擋住等非法點擊 | 否 | 沒有改變狀態，直接忽略。 |
| 合法但沒有立即消除 | 否 | 可能是在準備下一隻貓或連鎖。 |
| 能過關但不是最高分 | 否 | 仍是正確答案，只影響星等或分數。 |
| `CanFinish(resolve(S,a)) = false` | 是 | 已確認此步進入死路。 |
| 搜尋超時或隨機性無法判定 | 否 | 標記 `uncertain`，不可以誤判玩家。 |

若某一個可玩的狀態沒有任何 safe 操作，這是題庫或關卡生成器錯誤，不是玩家錯誤。上線前的驗證器必須擋下這種關卡。

## 提示的正確性與多樣性

現行的即時貪心提示只比較「這一欄現在清幾隻」與「清完後有多高」，可能拿到短期最高分，卻堵住下一段唯一救援路線。配置模式若永遠取 `level.solution` 的第一個位置，也只代表作者保存的一條路。

新的提示流程：

1. 列出所有合法操作。
2. 對每個操作完整執行落下、波次、四／五連、重力與目標更新。
3. 用 `CanFinish` 過濾出 `safe` 操作。
4. 對 safe 操作計算路線品質；不能直接取第一個 witness。
5. 若多個選項接近，顯示多個安全欄位或使用「建議」文字。

```text
hintScore(a) = 0.35 × winRobustness
             + 0.25 × requiredGoalProgress
             + 0.20 × futureSafeBranches
             + 0.10 × expectedCascade
             + 0.10 × heightSafety
```

- `winRobustness`：固定隊列下可完成的路線數；隨機段使用多 seed 成功率。
- `requiredGoalProgress`：是否推進目前缺少的四連、五連、連鎖或斜線計數；整理步要看未來可完成性。
- `futureSafeBranches`：下一回合還剩多少 safe 選擇，避免提示把玩家帶進唯一窄路。
- `expectedCascade`：預期波次數，但不能為了高 Combo 犧牲完成率。
- `heightSafety`：最高欄距離頂端的餘裕。

最高分與第二高分差距小於 5% 時，提示至少標出兩個安全選擇。提示文字要說明：

- 要點哪一欄或哪一格。
- 這一步是直接消除、先整理，還是準備下一波。
- 會推進哪個目標計數。
- 模擬預期第一波清除量與最多連鎖深度。

提示只有在完整搜尋確認後才可以說「會完成」。如果只是「有機會」，就要說「可能」或「建議」，不能把預測寫成保證。

這種直接驗證合法操作與完成路線的方式，比只抽樣幾條遊戲路線更適合確認關卡真的可玩。[Playtesting Match 3](https://odr.chalmers.se/server/api/core/bitstreams/fe7b02d0-0052-4d92-9cae-67dd71bc2c28/content)

## 三條生命與回復規則

每關初始 `lives = 3`。生命表示「已被證明的死路錯誤」，不是失誤次數計數器。

一次落下是交易式處理：

1. 保存落下前完整狀態：棋盤、目前貓、隊列、目標與生命。
2. 模擬玩家點擊，完整結算所有 wave。
3. 若結果仍有完成路線，正式提交；即使沒有立即消除，也不扣生命。
4. 若沒有任何完成路線，回復落下前狀態，扣 1 條生命，顯示「這一步會封死目前的完成路線」。
5. 生命歸零才顯示失敗。

錯誤操作應在提交前回復，不應讓玩家留在必敗棋盤上。這個回復是一次落下的原子交易，不是失敗後的復活；生命歸零後必須真正結束本局。

失敗後不提供「看廣告繼續」、清底排、加賽或回到連鎖中段。廣告只可放在玩家主動請求提示、過關獎勵加倍等不改變失敗盤面的停頓點；取消、無填充或錯誤回呼時，不扣任何遊戲資源。獎勵式廣告應提供額外價值，不能靠故意生成死路逼觀看。[Google AdMob rewarded video case study](https://admob.google.com/home/resources/deguci-games-boosts-arpdau-by-10-percentage-with-rewarded-video/)

## 淘汰所有失敗後回復方式

以下規則全部不再使用：

- 連鎖自動播放完後，從「已消除一部分的失敗盤面」繼續。
- 看影片後，把玩家送回已經失敗的連鎖中段或停止畫面。
- 只保留已消除成果，再要求玩家從剩餘貓咪繼續解。
- 三條生命用完後，以廣告恢復生命並接回同一局。
- 碰頂後清除底排或時間到後增加額外落下次數。

這些回復點發生在玩家已經失去選擇之後，玩家不知道是哪一步造成死路，也可能回到根本無解的盤面。它們不是復活，而是把錯誤狀態延長。

`checkpoint` 只在一次操作的交易期間暫存，不是失敗後的存檔：

```text
操作前保存 S0
→ 模擬放貓與完整連鎖
→ safe：提交結果，成為下一次操作前的狀態
→ dead：恢復 S0，扣生命，不提交這次落下
```

因此，連鎖動畫一旦開始就完整播放，不能在中途插入玩家選擇；如果完整結果是 `dead`，只在這次操作提交前回到 `S0` 並扣一條生命。若生命歸零，狀態進入 `failed`，只能整關重玩。舊有的「撤銷」若保留，只能是玩家在下一步前主動使用的便利功能，不能修補已播放完的失敗連鎖。

## 可見的三連、四連、五連與斜線目標

關卡可以宣告一個主要救援目標，以及最多兩個可讀的 pattern 目標：

```ts
goals: {
  rescued: 24,
  patterns: {
    minLine4: 1,
    minLine5: 0,
    minCascadeDepth: 2,
    minCascadeTurns: 0,
    minDiagonalRuns: 0
  }
}
```

計數來自 wave 開始前的「最大直線 run」，不是清掉幾隻貓：

- `minLine4`：真正四格同方向直線的次數；五連不重複算四連。
- `minLine5`：真正五格以上同方向直線的次數；T、L、十字五格不算。
- `minCascadeDepth`：單一回合最大的 wave 數；要求 2 就是至少一次 ×2。
- `minCascadeTurns`：有兩波以上的玩家回合總數。
- `minDiagonalRuns`：只有關卡明確設定 `matchMode: diagonal` 才計算；普通落下不偷偷啟用斜線。

目標分成兩種：

- 通關目標：救援數量加最多一個 pattern 條件。
- 星等／挑戰目標：例如再做一次五連或三波連鎖，不影響基本通關。

這樣玩家看到的是「還需要一次四連」，而不是在不知道答案的情況下被生命懲罰。提示可以說：「推薦欄位會先清 3 隻，落下後有機會完成四連」；只有搜尋確認時才可說「會完成四連」。

## 15–100 關的公開目標

| 關卡 | 必要目標 | 提示重點 | 設計限制 |
| --- | --- | --- | --- |
| 15–19 | 只要求救援數量 | 顯示 safe 欄位；教玩家整理步也可能正確 | 三條生命，但合法步不應輕易進死路 |
| 20–29 | 救援；二波連鎖先作星等 | 顯示「先整理」或「現在消除」 | 不因沒有立即消除扣命 |
| 30–39 | 救援；後段可要求 1 次四連 | 顯示四連完整路線與剩餘分支 | 至少兩條完成路線 |
| 40–49 | 救援＋1 次四連 | 顯示橫／直方向與爆發範圍 | 四連失敗但仍可通關不扣命 |
| 50–59 | 救援＋1 次五連 | 顯示五連會清同色 | 不同時要求五連與高 Combo |
| 60–69 | 救援＋最大二波或兩次二波 | 顯示第一波到第二波的因果 | 同時兩條線不算二波 |
| 70–79 | 救援＋斜線挑戰章 | 顯示斜線模式與剩餘次數 | 專用教學、多解、明確圖示 |
| 80–89 | 救援＋最多一個四／五連或連鎖目標 | 只提示能推進缺口的 safe 路線 | 障礙最多一種 |
| 90–100 | 救援＋一個熟練目標 | 顯示兩條以上安全路線 | 增加演出與選擇，不增加隱性死路 |

斜線要成為長期玩法，就要明確成為一個模式：關卡開始顯示斜線圖示、規則與計數。普通落下規則不能突然讓斜線生效。

## 100 關以後的長期內容

不要用「每一關增加一種顏色」無限堆高難度。以十關一章循環生產：

- 1 關新規則展示。
- 2 關單一規則練習。
- 2 關舊規則變形。
- 1 關呼吸關，降低壓力但保留高分路線。
- 2 關已學規則組合。
- 1 關支線或斜線挑戰。
- 1 關章節王關，給多安全分支與更強演出。

每章只增加一個理解成本，再用棋盤形狀、隊列節奏、貓咪主題、救援目標與動畫回饋製造新鮮感。難度分數每十關要下降一次，不能無限上升。

長期內容分三條線：

1. 主線章節：固定規則、固定解法品質、逐章解鎖。
2. 每日／每週挑戰：固定 seed 的短關卡，追求四連、五連與最高 Combo，不影響主線。
3. 變體與裝飾：換隊列、外觀、背景與貓咪演出，但每個變體都要重新跑可解性與生命判定。

100 關只是第一個規則循環，不是遊戲終點。後續可以重用已驗證的玩法組合與美術主題，但不能只把數字變大。廣告收入應建立在提示與過關獎勵加倍等玩家主動選擇的價值上，而不是故意製造錯誤關卡。

## 必要測試

1. `safe`、`dead`、`uncertain` 三種判定不能混用。
2. 合法但無立即消除的整理步不扣生命。
3. dead 操作回復到操作前，隊列與 seed 不變。
4. 三條生命歸零才失敗；失敗後不能用廣告恢復或接回本局。
5. 多條完成路線時提示不宣稱唯一答案。
6. 四連、五連、連鎖與斜線計數使用 wave 開始前的最大 run。
7. 普通落下關不會計入斜線目標。
8. 每關至少兩條 witness；章節王關至少三條。
9. 相同 seed 與相同操作必須得到相同棋盤、隊列、波次、分數與目標進度。
10. 失敗連鎖不能以半局盤面繼續；若是該次落下被判定為 `dead`，只在提交前退回該次操作開始前的狀態，不能在失敗後使用這個狀態繼續。
